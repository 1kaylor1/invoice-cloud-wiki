# wiki-lint：Wiki文章校验 Agent

## 触发方式

用户输入 `/wiki-lint <文件路径>` 时启动本流程。

---

## 第一层：格式lint（纯规则校验）

### 通用规则（所有文章类型）

逐条检查以下规则，不通过则自动修复：

1. 文件顶部必须有 YAML frontmatter（`---` 包裹）
2. frontmatter 必须包含且仅包含以下5个字段：`type` / `title` / `description` / `updated` / `channel`
3. `type` 值只能是 `runbook` / `explainer` / `readme` 三选一
4. `updated` 格式必须是 `YYYY-MM-DD`
5. `description` 不超过50字
6. `description` 不能与 `title` 完全相同
7. `channel` 值只能是 `金蝶中国渠道` / `发票云自营渠道` / `通用` 三选一
8. 正文至少有一个 H2 标题（`##`）
9. 正文字数大于50字
10. `related` 字段中列出的文件必须实际存在（用相对路径检查）
11. 正文内链 `[文字](路径.md)` 指向的文件必须实际存在

### runbook 专项规则

当 `type: runbook` 时，额外检查：

1. **阻断**：必须包含 `## 适用场景`
2. **阻断**：必须包含 `## 操作步骤`
3. **阻断**：`## 操作步骤` 下至少有一个 H3 子标题（`###`）
4. **阻断**：H3 步骤标题必须以 `第X步：` 或 `X.` 开头（X为数字或汉字数字）
5. **阻断**：步骤数量不少于2个
6. **警告**：建议包含 `## 申请须知`
7. **警告**：建议包含 `## 常见问题`

### explainer 专项规则

当 `type: explainer` 时，额外检查：

1. **阻断**：至少包含一个 H2 标题（名称不限）
2. **警告**：正文字数建议大于200字

### 格式lint执行规则

- 发现阻断问题 → 自动修复 → 重新检查，最多循环3轮
- 3轮后仍有阻断问题 → 终止流程，报告给用户，说明哪条规则无法自动修复，需要用户手动处理
- 警告问题记录下来，不阻断流程，在最终报告中展示
- 格式lint全部阻断项通过后，进入第二层

---

## 第二层：内容lint（AI语义校验）

### 检查项

1. **阻断**：内容是否和标题匹配（如标题叫"旗舰版激活流程"但内容讲的是标准版）
2. **阻断**：步骤是否完整、有无跳跃（如第一步→第三步，中间缺了第二步）
3. **警告**：内链逻辑是否合理（链接存在不等于链接有意义）
4. **警告**：与 `related` 文章是否有明显冲突（读取related文章后对比）
5. **警告**：是否有信息孤岛（文章提到某个概念但没有链接到对应说明文档）
6. **警告**：术语是否统一（如"旗舰版"和"企业版"混用）
7. **警告**：内容是否超出标题/description定义的范围（文章包含了标题和description未提及的内容，可能是未经确认的信息）
8. **警告**：runbook完成后是否有明确的后续操作——如有，是否用内链指向了后续文章；如后续文章未写完，是否标注了【待补充链接】

### 内容lint执行规则

- **严禁修改**：YAML frontmatter 任何字段、标题层级结构、必填标题名称
- 只修改正文语义内容
- 发现阻断问题 → 自动修复 → 重新跑内容lint
- 警告问题记录下来，在最终报告中展示
- 内容lint全部阻断项通过后，生成确认报告

---

## 第三层：确认报告

两层lint全部通过后，向用户输出以下报告，**等待用户确认，不自动写入**：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📄 文章：<文件名>
类型：<type值> | 渠道：<channel值>
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

✅ 格式lint：通过
✅ 内容lint：通过

📝 格式修改记录：
- <修改项1>
- <修改项2>（如无修改则写"无"）

📝 内容修改记录：
- <修改项1>
- <修改项2>（如无修改则写"无"）

⚠️ 警告项（请确认）：
- <警告1>
- <警告2>（如无警告则写"无"）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
确认写入wiki吗？输入"确认"后保存文件。
```

用户输入"确认"后，保存修改后的文件到原路径，流程结束。
用户输入"取消"或提出修改意见，按用户要求处理后重新输出报告。
