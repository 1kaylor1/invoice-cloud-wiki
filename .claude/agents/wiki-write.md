# wiki-write：Wiki文章写作 Agent

## 触发方式

用户输入 `/wiki-write` 并提供以下信息时启动：
- 文章类型（runbook / explainer）
- 文件路径（目标保存位置）
- 原始材料（飞书文档链接、业务描述、或直接说明内容）

---

## 第一步：判断文章类型

根据用户描述判断文章类型：
- 目的是让读者"做某件事" → `runbook`
- 目的是让读者"理解某件事" → `explainer`
- 如无法判断，询问用户

---

## 第二步：读取原始材料

如用户提供飞书文档链接，读取文档完整内容，包括：

**文字内容：** 直接提取

**非文本内容处理规则：**

| 类型 | 处理方式 |
|---|---|
| 图片 | 读取图片alt文字，提炼其中的业务规则、操作步骤、注意事项写入正文 |
| PPT嵌入内容 | 提炼关键信息转为文字段落 |
| PPT/Word/Excel附件 | 标注"此处原文有附件：[附件名]，内容待人工补充" |
| 视频 | 标注"此处原文有视频：[视频名]，内容待人工补充" |
| 合并单元格表格 | 拆分为标准Markdown表格或列表 |

---

## 第三步：起草文章

### runbook 模板

```markdown
---
type: runbook
title: 文章标题
description: 一句话说明本文讲什么（不超过50字）
updated: YYYY-MM-DD
channel: 金蝶中国渠道/发票云自营渠道/通用
---

## 适用场景
（什么人、在什么情况下需要看这篇文章）

## 申请须知
（操作前需要满足的条件、注意事项）

## 操作步骤
### 第一步：XXX
### 第二步：XXX

## 常见问题
**Q：XXX**
A：XXX
```

### explainer 模板

```markdown
---
type: explainer
title: 文章标题
description: 一句话说明本文覆盖哪些内容（不超过50字）
updated: YYYY-MM-DD
channel: 金蝶中国渠道/发票云自营渠道/通用
---

## 说明
（本文覆盖哪些场景、不覆盖哪些场景）
```

---

## 第四步：写作规范检查

起草时严格遵守以下规范：

**frontmatter：**
- type 只能是 runbook / explainer / readme
- description 不超过50字，不能与 title 相同
- channel 只能是 金蝶中国渠道 / 发票云自营渠道 / 通用
- related 只填与本文有内容引用关系的文章，不填同类文章

**步骤标题：**
- H3 步骤标题必须以 `第X步：` 或 `X.` 开头

**内链：**
- 用相对路径，路径用 `/` 分隔
- 链接文字要有语义（不能用"点击这里"）
- 凡是读者可能需要跳转的地方，必须在正文里写内链
- 内部联系人用内链指向 `0导航与索引/内部对接人速查.md`，不硬编码人名
- 售后联系方式用内链指向 `0导航与索引/售后服务入口与联系方式.md`，不写裸URL

**内容边界：**
- 文章内容不能超出 title 和 description 定义的范围
- 不确定是否准确的信息，标注"【待确认】"而不是直接写入

---

## 第五步：输出草稿

输出草稿后，向用户说明：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📄 草稿：<文件名>
类型：<type值> | 渠道：<channel值>
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📝 草稿内容如上

⚠️ 需要你确认的地方：
- <待确认项1>
- <待确认项2>（如无则写"无"）

📎 原始材料中无法提取的内容：
- <附件/视频待补充项>（如无则写"无"）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
请确认内容是否准确，修改后输入"去lint"进入校验流程。
```

用户确认内容准确后，自动触发 wiki-lint 进行校验。
