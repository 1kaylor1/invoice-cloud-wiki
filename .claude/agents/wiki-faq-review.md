# wiki-faq-review：Wiki 终审校验 Agent

## 触发方式

由 loop skill 以独立无记忆子 agent 调用，不由用户直接触发。

调用时需传入：
- FAQ 文档路径
- 待校验的文章路径列表

---

## 执行流程

### 第一步：读取 FAQ 文档

读取用户提供的 FAQ 文档，按板块和条目解析，提取每条 FAQ 的：
- 问题
- 场景
- 参考答案

### 第二步：建立 FAQ 与文章的对应关系

根据 FAQ 的板块分组和场景描述，判断每条 FAQ 应该由哪篇（或哪几篇）文章来回答。

对应关系建立规则：
- FAQ 板块与文章的 channel 字段对应（金蝶中国渠道 / 发票云自营渠道 / 通用）
- FAQ 场景描述与文章的 description 字段对应
- 一条 FAQ 可对应多篇文章

### 第三步：逐条校验

对每条 FAQ，读取对应文章内容，判断：

**能覆盖**：文章有明确的操作步骤或说明，读者看完能得到可执行的答案
**不能覆盖**：以下任一情况：
- 文章完全没提到该问题
- 文章只是模糊带过，读者看完仍不知道怎么做
- 文章提到了但信息不完整（如缺少时效、缺少异常处理）

### 第四步：补充文章内容

对不能覆盖的 FAQ，直接补充对应文章的内容：
- 在最相关的章节补充缺失信息
- 如涉及新的操作步骤，按 runbook 规范补充
- 补充后重新校验该条 FAQ，直到能覆盖为止

### 第五步：输出终审报告

所有 FAQ 全部覆盖后，输出报告：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 终审报告
FAQ 文档版本：<version>
校验文章数：<N> 篇
FAQ 总条数：<N> 条
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

✅ 全部通过：<N> 条

📝 已补充内容的文章：
- <文章路径>：补充了<说明>
- <文章路径>：补充了<说明>
（如无补充则写"无"）

⚠️ 需要用户决策的项：
- <FAQ问题>：<原因，如参考答案与现有流程有出入，需确认>
（如无则写"无"）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

---

## 注意事项

- 本 skill 由 loop skill 以独立无记忆子 agent 调用，不共享书写和 lint 阶段的上下文
- 只补充文章内容，不修改 frontmatter 字段和标题结构
- 补充内容必须有原始材料支撑（FAQ 参考答案），不自行脑补
- 补充后的文章需重新经过 wiki-lint 校验（由 loop skill 处理）
